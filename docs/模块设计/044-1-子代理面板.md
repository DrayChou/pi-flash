## 0. 概念分层(先对齐,防再混淆)

```
Agent 定义(profile)= 用户资产 = 「类」     ← Settings-子代理页管理
  预制:扩展随包出厂(只读,可复制为自定义)
  自定义:用户完全所有(可建/改/删/分享/进项目 git)
子代理实例 = 运行记录 = 「对象」            ← 子代理面板监视
  委派产生的运行记录(childId/会话文件/状态/usage)
pi-subagents 扩展 = manager(机制层)        ← 不拥有定义,只消费目录
```

**存放 = 用户资产惯例,非扩展私有数据**(2026-10-19 修正:曾错误地按"扩展
归属"推导位置):

| 来源 | 路径/载体 | 说明 |
|---|---|---|
| 自定义 | `~/.pi/agent/agents/*.md` | 用户完全所有:可建/改/删;同名覆盖内置 |
| 内置 | 扩展代码内常量 | 随 pi-subagents 出厂,只读,可复制为自定义 |

**解析顺序(同名覆盖)**:自定义 > 内置;都无 → `PROFILE_INVALID`。
2026-10-19 拍板:**①不分项目级**(subagent 不分项目,只分内置/自定义);
**②不做包分发**(PF subagent 是内部组件,不对外发布,无 pi install 入口);
**③编辑走 PF 表单**,不让用户直写明文(§2.1)。

**为什么不照搬 dsh 的存放**:dsh 的 preset 是 cordis.yml 组合里的声明式
插件行(新建 = bundle 补丁 + plugin_manager 安装,无文件目录)——那是它
"一切皆插件"架构的产物。pi 的资源哲学是**目录发现**(skills/prompts/
themes/extensions 全是目录),agent 定义用 `agents/` 目录与生态完全同构;
"安装/分享"层用 **pi packages** 对齐 dsh 的 plugin_manager(§6.3),概念
对齐、机制用 pi 自有的,零自造轮子。

## 1. 子代理面板(运行实例层)

### 1.1 一句话

操作栏常驻按钮「子代理面板」(运行中带计数徽标),点开从操作栏向下延伸的
浮层(遮上半内容区,点外/ESC/✕ 关闭),列出**当前会话**的子代理 catalog,
整行点击 = 以正式 tab 打开子会话。

### 1.2 职责边界

| 做 | 不做 |
|---|---|
| 当前会话子代理 catalog 一览(全历史) | ❌ 派发任务(派发只从对话发起) |
| 运行中实时刷新(轮询父会话文件) | ❌ 跨会话聚合(v2 面板内切换后补) |
| 打开子会话(正式 tab) | ❌ Agent 定义管理(§6 Settings 页) |

### 1.3 交互稿

```
会话操作栏: [📁会话目录] [⌥打开终端] [⟳ 子代理面板 ②]
──────────────────────────────────────────────────────
        ┌ 子代理面板 ─────────────────────── ✕ ┐
        │ ⟳ arch-review   spawn·d1  45s       │
        │ ⟳ test-writer   spawn·d1  12s       │
        │ ✓ usage-check   1,234 tok   ↗      │
        │ ⊘ bg-note   ABORTED             ↗   │
        └─────────────────────────────────────┘
```

- 入口:`session_fn_bar` 「会话目录」「打开终端」之后;运行中计数徽标
  (N = phase ∈ provisioning/active)
- 浮层:`ui/overlay.rs` `layer()`(点外/ESC/occlude 内置);定位 = 操作栏
  正下方,宽 ≈ 内容区 60%,最大高 = 内容区上半
- 行:状态徽标(⟳ 黄 / ✓ 绿 / ⊘ 橙+ABORTED / ✕ 红+分码)+ label(退
  childId)+ `provider·d{depth}` + 耗时或 tokens;整行点击 = 打开子会话
  tab 并关闭浮层
- 空态:「本会话还没有子代理——在对话里让我委派任务即可」

### 1.4 数据契约

事实源 = **父会话 JSONL 的 `subagent/descriptor` custom entry**(扩展每次
activation 状态变化实时 `appendEntry`):

```json
{ "version":1, "childId":"sub-1", "provider":"spawn", "label":"arch-review",
  "depth":1, "sessionFile":"…child.jsonl", "phase":"active",
  "stopReason":"completed", "errorCode":"…", "startedAt":"…", "updatedAt":"…" }
```

读取设施(pi-link):

```
subagent_catalog::read_catalog(session_file, from_offset)
  → { rows: Vec<CatalogRow>, next_offset: u64 }
```

- 流式扫 descriptor,同 childId 末条覆盖;`from_offset` 增量续读(面板
  打开期间 1s 轮询只读新增字节)
- 宿主状态:`subagent_panel: Option<{offset, rows}>`——Some = 打开(轮询
  启动),None = 关闭(轮询停止)

## 2. Settings-子代理页(Agent 定义管理层)

### 2.1 定位与表单化(2026-10-19 拍板)

**Agent 定义的类型层管理**(面板是实例层)。形态与 042 模型管理同构
(左列表右编辑)。

**配置项组件化,不让用户直写明文**。理由:①防小白(YAML frontmatter
对普通用户不可用);②防恶意注入(明文可手改即注入面;配置后续由 PF
**单独管理存储**,不再依赖手工改明文 md)。

表单化边界:**PF 只表单化 v1 已定字段集**(§3);扩展未来新增的未知字段
PF **原样透传不碰**——既防小白又不写死 schema 契约。人格用「追加到
默认/完全替换」二档 seg 呈现(存为 appendSystemPrompt / systemPrompt),
用户不感知两个字段名。

### 2.2 交互稿

```
Settings → 子代理
┌ 列表 ─────────────────┐  ┌ 表单详情 ─────────────────┐
│ 内置(随扩展,只读)      │  │ code-reviewer [自定义][覆盖内置]│
│  ○ explorer  只读探索  │  │ 描述     [代码评审_________] │
│ ──────────────────────│  │ 模型     [deepseek-chat ▾]  │
│ 自定义 ~\.pigents    │  │ 轮次预算 [− 15 +] 默认25     │
│  ● code-reviewer 覆盖* │  │ 人格     [追加到默认|完全替换]│
│  ● broken-scan 损坏    │  │ 系统提示词 [多行文本________] │
│                        │  │ 工具     (read)(grep)(glob)…│
│ [+ 新建子代理]         │  │ ────────────────────────── │
│                        │  │  [放弃] [保存]  ●未保存 Ctrl+S│
└────────────────────────┴────────────────────────────┘
```

- 列表两组:**内置(只读)** / **自定义**;覆盖内置的自定义条目加
  「覆盖内置」badge
- 表单字段:描述(文本)/模型(下拉,留空跟随会话)/轮次预算(步进器,
  默认 25)/人格(二档 seg)/系统提示词(多行文本)/工具(chips 多选)
- 动作:放弃 / 保存(Ctrl+S,未保存黄点);删除进**回收站**
- 内置态:表单只读灰化 + [复制为自定义](fork 进自定义目录)——对齐
  dsh「按 id 覆盖内置 preset」语义,载体为文件覆盖
- 损坏态:红条错误(解析失败定位)+ [打开文件修复](源码编辑器,表单化
  的唯一源码逃生口)+ [删除];fail-closed 是运行时职责,PF 保证可修

### 2.3 存储演进

近期:单一事实源 = `~/.pi/agent/agents/*.md`(CLI `pi -e`、PF、扩展三方
共享);Settings 页 = 表单编辑的用户面,读写该目录。
后续(用户拍板方向):**配置由 PF/扩展单独管理存储**(结构化,非明文 md),
防注入与误改;UI 表单层与存储格式解耦,切换对用户透明。

## 5. 决策记录:为什么弃 setWidget 挂件

曾方案:扩展 `ctx.ui.setWidget(key, lines, {placement:"belowEditor"})`
流式推送状态行,PF 渲染挂件。弃用理由:

1. `widgetLines` 只能是**字符串数组**(RPC 模式组件工厂不支持)——交互
   (整行点击打开子会话)要 hack 行文本格式,PF 再解析,脏;
2. 推模型依赖扩展进程存活;改拉模型后 **descriptor 落盘即事实源**,PF 重启/
   子代理完成/宿主崩溃全不丢状态;
3. 操作栏按钮 + 浮层是 PF 既有范式(会话目录/打开终端同栏),入口常驻、
   可扩展。

setWidget 通道本身保留:PF 已解析该记录(protocol.rs/ext_ui.rs),未来
通用扩展挂件仍可用,与本面板无耦合。
