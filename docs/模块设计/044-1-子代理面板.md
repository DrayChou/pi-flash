# 044-1 子代理面板(宿主侧)

> 状态:**设计定稿,待实现**。配套 [044-subagent宿主设计](044-subagent宿主设计.md)
> (本文是其「聚合视图」与「子会话跳转」两条的落地设计)与
> [045-subagent管理](045-subagent管理.md)(扩展侧)。
> 定案(2026-10-19,与用户对齐):**操作栏按钮 + 浮层面板**,弃 setWidget
> 流式挂件方案(决策记录见 §5)。面板名:**【子代理面板】**。

## 0. 一句话

操作栏常驻按钮「子代理面板」(运行中带计数徽标),点开从操作栏向下延伸的
浮层(遮上半内容区,点外/ESC/✕ 关闭),列出**当前会话**的子代理 catalog
(状态/耗时/tokens),整行点击 = 以正式 tab 打开子会话。

## 1. 职责边界(它做什么/不做什么)

| 做 | 不做 |
|---|---|
| 当前会话子代理的 catalog 一览(全历史:运行中/完成/中断/失败) | ❌ 派发任务——派发只从对话发起(主代理调 `agent` 工具) |
| 运行中实时刷新(轮询父会话文件) | ❌ 跨会话聚合(v2 面板内切换后补) |
| 打开子会话(正式 tab,复用 `open_session`) | ❌ 在面板内操作子代理(send/interrupt 走对话/控制工具,后续再评估是否上浮层) |
| 完成通知的落点补充(notify 已有) | ❌ token 账本(usage 随工具结果已在卡内) |

## 2. 交互稿

```
会话操作栏: [📁会话目录] [⌥打开终端] [⟳ 子代理面板 ②]      ← 新按钮
──────────────────────────────────────────────────────
        ┌ 子代理面板 ─────────────────────── ✕ ┐
        │ ⟳ arch-review   spawn·d1  45s       │   ← 整行可点
        │ ⟳ test-writer   spawn·d1  12s       │
        │ ✓ usage-check   1,234 tok   ↗      │
        │ ⊘ bg-note   ABORTED             ↗   │
        └─────────────────────────────────────┘
   (浮层自操作栏向下延伸,遮上半内容区;点外/ESC/✕ 关闭)
```

### 2.1 入口按钮

- 位置:`session_fn_bar`(session/mod.rs)「会话目录」「打开终端」之后,`|` 区隔
- 形态:图标 + 「子代理面板」;**运行中计数徽标**(⟳ N,N = phase ∈
  provisioning/active 的数量);N=0 时无徽标
- 数据:按钮态随 catalog 刷新(见 §4);PF 重启后从父会话文件恢复

### 2.2 浮层

- 外壳:`ui/overlay.rs` 的 `layer()`(点外关闭/ESC/occlude 全部内置);
  卡片定位 = 操作栏正下方,宽度 ≈ 内容区 60%,最大高度 = 内容区上半
- 头部:「子代理面板」+ 当前会话名 + ✕
- 行(整行可点 = 打开子会话 tab 并关闭浮层):
  - 状态徽标:⟳ 运行中(黄)/ ✓ 完成(绿)/ ⊘ 中断(橙,附 ABORTED)/
    ✕ 失败(红,附分码)
  - 文本:label(缺省退 childId)+ `provider·d{depth}` + 耗时(运行中为已
    进行时长)或 tokens
  - 全历史排序:start 时间倒序(最新在上)
- 空态:「本会话还没有子代理——在对话里让我委派任务即可」

### 2.3 打开子会话

- `chat.open_session(子会话文件, false, cx)` → 正式 tab(与普通会话一致:
  可续跑、可 fork、transcript 完整)——**子会话是一等公民会话,不做只读
  特殊化**
- 打开后浮层关闭

## 3. 数据契约

**事实源 = 父会话 JSONL 里的 `subagent/descriptor` custom entry**。扩展
(pi-subagents)在每次 activation 状态变化时 `appendEntry` 实时落盘,字段:

```json
{ "version":1, "childId":"sub-1", "provider":"spawn", "label":"arch-review",
  "cwd":"…", "depth":1, "sessionFile":"…child.jsonl", "composition":{…},
  "phase":"active|completed|interrupted|failed|provisioning",
  "stopReason":"completed", "errorCode":"…", "startedAt":"…", "updatedAt":"…" }
```

### 3.1 读取设施(pi-link)

```
subagent_catalog::read_catalog(session_file, from_offset)
  → { rows: Vec<CatalogRow>, next_offset: u64 }
CatalogRow = { child_id, phase, label, provider, depth, stop_reason,
               error_code, session_file, started_at, updated_at }
```

- 流式逐行扫 `"customType":"subagent/descriptor"`,**同 childId 末条覆盖
  前条**(descriptor 是全量快照语义)
- `from_offset` 增量续读(会话文件只追加;面板打开期间 1s 轮询只读新增
  字节,大文件不重扫);首次调用 from_offset=0 全扫
- 复用 sessions.rs 的流读纪律(不整文件进内存)

### 3.2 宿主状态(app)

```
Chat.dlg.aux 或 session 域新增:
  subagent_panel: Option<{ offset: u64, rows: Vec<CatalogRow> }>
  —— Some = 面板打开(挂 1s 轮询定时器);None = 关闭(轮询停止)
打开 = 全扫一次 + 启动轮询;关闭 = 清状态停轮询(轮询只存在于面板打开期)
```

## 4. 实现拆分

| 步 | 内容 | 位置 |
|---|---|---|
| 1 | `read_catalog` 设施 + 单测(全扫/增量/末条覆盖/损坏行跳过) | `pi-link/src/subagent_catalog.rs` |
| 2 | 操作栏按钮 + 徽标 + 浮层渲染 + 行点击 open_session + 轮询状态机 | `session/mod.rs`(session_fn_bar)、新 `session/subagent_panel.rs`、shell/render.rs(overlay 挂载点) |

## 5. 决策记录:为什么弃 setWidget 挂件

曾方案:扩展 `ctx.ui.setWidget(key, lines, {placement:"belowEditor"})`
流式推送状态行,PF 渲染挂件。弃用理由:

1. `widgetLines` 只能是**字符串数组**(RPC 模式组件工厂不支持)——交互
   (整行点击打开子会话)要 hack 行文本格式,PF 再解析,脏;
2. 数据是推模型,依赖扩展进程存活;面板改拉模型后,**descriptor 落盘即
   事实源**,PF 重启/子代理跑完/宿主崩溃全都不丢状态;
3. 操作栏按钮 + 浮层是 PF 既有范式(会话目录/打开终端同栏),入口常驻、
   命名直白,可扩展(profile 管理、跨会话视图后补进同一面板)。

setWidget 通道本身保留:PF 已解析该记录(protocol.rs/ext_ui.rs),
未来通用扩展挂件仍可用,与本面板无耦合。

## 6. 边界与后续

- v1 范围 = 当前会话;跨会话(项目级)聚合 = 面板内范围切换,后补
- 子会话内的控制操作(send/interrupt)暂不在面板;需要时走对话内控制工具
  (`subagent_send`/`subagent_interrupt`),面板是否上行这些操作待真实
  使用反馈
- 面板打开期间的 1s 轮询只读增量字节,待实测长会话(>50MB)下的成本
