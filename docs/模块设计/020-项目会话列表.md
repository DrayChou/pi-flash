## 伪标签（draft 已发送、pi 未落盘的占位行，2026-10-13）

侧栏的会话标签 = 磁盘扫描（`refresh_sessions`），而 pi 的会话文件要等首条
user/assistant 消息才落盘（session-manager `_hasConversation`，#10000），
新会话冷启还要等 node 进程 boot（1-3s）——没有伪标签时，「发送消息 → 侧栏
出现新标签」之间有一段无反馈空窗。

- **挂**：`optimistic_send`（prompt/steer/微信远程共用漏斗）发现 runtime
  还是 draft（`file.is_none()`）→ emit `SessionEvent::PendingTab(Some(首行
  预览))` → Chat 的 `pending_tabs` 插入占位行。发送的同一帧上侧栏：样式与
  真标签同款（行高/字号/选中色），左侧状态槽 = spinner，标题 = 消息首行
  （真标签落地后的 preview 与它一致，衔接无跳变）。位置 = 归属项目组会话
  行最前（Flat 模式列表最前；组还不存在则 Title 后置顶）。折叠组里照常
  显示；无 hover 卡（rename/delete 依赖真实文件）。
- **换真身**：首条用户消息事件到达时 runtime 调 `try_bind_reported_file`
  ——pi 报备过的 sessionFile 此刻已在盘上（先 appendMessage 再发事件），
  `follow_session_file` 的存在性守卫放行 → FileBound → `on_file_bound`
  迁移 pool key（draft-N → 路径）并摘掉伪标签，磁盘扫描的真标签接管。
  不等 AgentSettled 才绑定：否则「真标签已上侧栏、pool key 还是 draft-N」
  的窗口里点标签会 spawn 出 duplicate runtime。
- **撤**：三个确定「永远不会有文件」的时刻撤标签——prompt 被 preflight
  拒绝（无鉴权/无模型）、AgentSettled 时报备文件仍未落盘（prompt 被扩展
  接管，pi 没写过任何消息）、进程退出且未落盘。判定统一走
  `try_bind_reported_file`（绑定在途时返回 true 不误撤，避免闪烁）。
- **幻影绑定守卫**（伪标签的前置）：pi 在 SessionManager 构造期就把
  sessionFile 定死，启动期 get_state 带回的是还不存在的路径——
  `follow_session_file` 对 `!f.is_file()` 直接不绑定，boot 草稿保持
  draft 身份。副产品（改善）：「开了 app 没说话就关」不再用幻影路径覆盖
  last_open，下次启动恢复上一个真实会话。
- 伪标签是纯内存态：没落盘的 draft 重启后本就不存在，无需持久化。
