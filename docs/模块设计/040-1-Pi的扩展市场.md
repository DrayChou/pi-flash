## 0. 边界与结论

- **不嵌网页、不依赖 pi.dev 的 API**：`https://pi.dev/api/packages` 实测返回
  `{"ok":false,"error":"API routes are reserved for future features."}`，
  `/packages.json` 404；站点只有服务端渲染 HTML（`?name/type/sort/page=`
  表单，50 条/页，共 5407 条）。抓 HTML 不做主路径。
- **数据面 = npm registry 搜索 API**（站点自身的数据源）：
  `GET https://registry.npmjs.org/-/v1/search?text=keywords:pi-package&size=50&from=N&popularity=1&quality=0&maintenance=0`
  实测 200 / ~1s，返回 name、description、version、date、`downloads.monthly`、
  author、links、keywords。
- **类型/资源清单 = 单包 latest 清单**：
  `GET https://registry.npmjs.org/<name>/latest` → `pi` 键
  （`extensions/skills/prompts/themes/subagents/image/video`）。
  抽检 top-20：20/20 都带 `pi` 键，`pi.extensions` 存在即可判定「是扩展」。
- **写路径 = 与 040/082 同一条 vendored pi CLI 管道**（`pi install/remove/update`），
  市场页不自己动 `node_modules`、不自己写 `settings.json`。
- **不改 Settings 模块**（铁律）：市场页是**独立标准页**，设置页的代理/镜像类
  配置一律不加，网络兜底走环境变量（§9）。

## 2. 数据结构（pi-link/src/market/pi_ext_market.rs）

```rust
pub enum MarketKind { Extension, Skill, Prompt, Theme, Subagent }

pub struct MarketEntry {
    pub name: String,            // npm 名（含 scope，显示原样）
    pub description: String,
    pub version: String,         // latest
    pub monthly_downloads: u64,
    pub updated: String,         // registry 的 ISO 字符串，原样展示
    pub kinds: Vec<MarketKind>,  // 由 pi 清单推出；空 = 清单缺 pi 键
    pub repo: Option<String>,
}

impl MarketEntry {
    pub fn is_extension(&self) -> bool;      // kinds 含 Extension（过滤口径）
    pub fn install_command(&self) -> String; // "pi install npm:<name>"
}

/// 纯解析入口（单测主战场，不打网络）
pub fn parse_search_page(body: &str) -> Result<(Vec<MarketEntry>, usize), String>; // (页内条目, total)
pub fn parse_latest_manifest(body: &str) -> Result<Vec<MarketKind>, String>;
pub fn search_url(query: &str, from: usize, size: usize) -> String;              // 纯函数
pub fn latest_url(name: &str) -> String;                                        // scope 的 / → %2F
pub fn format_downloads(n: u64) -> String;                                      // 1.8M / 792.8K / 3.4K

/// 网络入口（阻塞，调用方在后台线程）
pub fn search(query: &str, from: usize, size: usize) -> Result<(Vec<MarketEntry>, usize), String>;
pub fn fill_kinds(entries: &mut Vec<MarketEntry>, kinds: &mut HashMap<String, Vec<MarketKind>>); // 并发 8，失败保留 kinds 空

/// 磁盘缓存：<PF数据目录>/pi-ext-market-cache.json（**只存首页快照，<100KB**）
/// 不做全量字典落盘/LRU/trim（见 §3.5）
pub struct HomeSnapshot {
    pub query: String,
    pub entries: Vec<MarketEntry>, // 上次上屏的那些条目（≤50）
    pub fetched_at: i64,
}
impl HomeSnapshot {
    pub fn load() -> Option<Self>;             // 坏文件/缺字段 → None，不 panic
    pub fn save(&self);                        // 原子写（tmp + rename），失败静默
    pub fn age_secs(&self) -> i64;
}
```

要点：

- **`is_extension` 是唯一过滤口径**：用户要求「只展示扩展」。`kinds` 为空（清单请求
  失败/包没写 `pi` 键但走约定目录）→ **放行**并标类型「—」，避免网络抖动把整页清空。
- 下载量排序：服务端用 `popularity=1&quality=0&maintenance=0` 逼近「最多下载」；
  `date`/名称排序客户端只对**当前页**成立 —— 该差异写进页面脚注，不承诺与官网排序逐条一致。
- 缓存：**只有一份首页快照**（6h TTL，仅作渲染提示；`MarketEntry.version` 用于
  「已装 vs 最新」比对）。不落盘全量字典，会话内 `HashMap<name, Vec<MarketKind>>` 足够。
  时序与取舍见 §3.5。

## 3. 数据流与页内状态机

```
// crates/app/src/market/pi_ext_market.rs
PiExtState {
    query: String,             // 搜索框镜像（TextInput on_change 写入）
    installed_filter: Filter,  // 未安装 | 已安装   （默认「未安装」，见 §5）
    entries: Vec<MarketEntry>, // 已过滤（is_extension）+ 已补 kinds 的列表，**上限 200 条**
    kinds: HashMap<String, Vec<MarketKind>>, // 会话内 kind 位（不落盘，几十 KB）
    total: usize,              // 服务端 total（用于「还有 N 条」提示）
    from: usize,               // 下一批起点（+= 50）
    loading: bool,             // 单飞闸：为真时不再发新页请求
    stale: bool,               // 当前 entries 来自磁盘快照、后台正在刷新
    error: Option<String>,     // HTTP/解析错误（页面顶部红条，可重试）
    offline: bool,             // 搜索失败 → 显示快照副本 + 黄条
    gen: u64,                  // 请求代际：换词 ++，回包 gen 不符即丢弃（013 search_gen 同款）
    scroll: UniformListScrollHandle,
}
```

一次拉页（全在后台线程，`cx.background_executor` 只做 timer；缓存与取舍见 §3.5）：

0. 页面打开时先读磁盘快照：命中则立即上屏 + `stale = true`（不置 `offline`），再走下面刷新；
1. `gen2 = ++gen`、`loading = true`；`search(query, from, 50)`；
2. 按 **10 条一批** 补全 kinds（批内并发 8，命中 `kinds` 表则跳过）→ 每批判定
   `is_extension` + 按 `installed_filter` 过滤（已装集合实时读 `cfg.mc_pkgs_global`，见 §6）；
3. 每批判完就回主线程 append（**不累计 50 条再上屏**，也绝不「上了再移除」）；
4. 最后一批才 `loading = false`、写磁盘快照、`notify`。

触发点：页面首次打开、搜索词变化（250ms 去抖）、筛选切换（客户端重算，0 请求）、
滚动到距底 300px（下一页）、重试按钮。

翻页上限 **200 条**（=4 页）：到顶后底部提示「用搜索词缩小范围」。不做 5400 条深度翻页
（npm 搜索分页深度未验证，收益也极低）。

## 3.5 性能与缓存策略（内存预算优先的简版）

**定位：网页级体验即可，不做重度优化。内存预算上限 ≈ 1MB，磁盘缓存 = 一个小文件。**
一句话：**进页面先用磁盘快照秒开，后台单次刷新；每页 1 次搜索 + ≤50 次清单请求，分批上屏。**

### 只留一层磁盘缓存（首页快照）

| 项 | 内容 |
|---|---|
| 文件 | `<PF数据目录>/pi-ext-market-cache.json`（一个市场一个文件） |
| 存什么 | **只有一组**：`{query, entries(上屏过的条目，≤50 条), fetched_at}` |
| 大小 | **<100KB**（50 条 × 约 300B） |
| TTL | 6h；过期只当渲染提示，仍可先上屏再刷新 |
| 写入时机 | 每次成功出页后覆盖写（原子写 tmp+rename，失败静默） |
| 不做 | **不做全量字典落盘、不做 LRU/trim、不做多 query 缓存** |

内存里额外只有两样：当前列表 `Vec<MarketEntry>`（**上限 200 条**）+ 会话内
`HashMap<name, Vec<MarketKind>>`（只存 kind 位，≤几十 KB），进程退出即丢。

### 进页面时序

```
点菜单 → 立即可渲染页壳
   ├─ 磁盘快照命中 → 直接上屏（0 网络，黄条不出现，只是内容可能过期）
   └─ 未命中       → 尾部 3 行占位骨架
      ↓ 单飞闸（loading 为真时不再发新页请求）
   搜索 1 次（~1.0s，size=50）
      ↓ 以 8 条为一批补清单（批内并发 8，一批 1.0-1.6s）
   每批判完 → 过滤 → append 上屏 → notify
```

- 冷启：首批 8 行 **~1.8-2.4s**，满 50 行 **~5.5-6.5s**（网页级；页壳与搜索栏 0 延迟）。
- 热回访：磁盘快照 **<50ms** 上屏，后台刷新完就地替换。
- 切 tab 回来 / 切「未安装↔已安装」：**0 请求**（状态与 kinds 都在内存）。
- 续页（滚到底）：同样「1 次搜索 + 分批清单」；`from` 累计到 **200 条**即停，
  底部提示「用搜索词缩小范围」（不追求 5400 条全可翻）。

### 明确不做的优化（省复杂度 / 省内存）

| 不做 | 理由 |
|---|---|
| 清单字典落盘 24h + LRU 1000 包 | 磁盘与代码复杂度换不到关键体验；会话内 HashMap 已够热路径 |
| 启动延迟加载预取首页 | 省掉「后台偷跑流量」这类争议，缓存只在用过后才有 |
| in-flight 请求去重集合、多页并发预热 | 单飞闸（`loading` + `gen`）已足够，网页级体验不需要 |
| 网络图片/预览图缓存 | 行内不显示图片（v2 再说） |
| 累积 1000 条 + 深度翻页 | 200 条封顶，内存稳定在几十 KB |
| 082 更新检测联动 | 市场页**绝不触发** 082（`npm view` 逐包 spawn，N×1s）；只读 `aux.plugin_updates` 既有结果 |

### 连接与限流（够用即可）

- 模块内 `static AGENT: OnceLock<ureq::Agent>`：keep-alive + gzip（实测不复用连接
  50 包要 6.0s，复用后 2.6s），`timeout 15s`，响应体截断 2MB。
- 清单补全并发 **8**（8→16 只省 0.4s，不值），`std::thread::scope` 手撸，不加新依赖。

### 失败处理（只两种）

| 情形 | 行为 |
|---|---|
| 搜索失败、磁盘快照可用 | 保留快照内容 + 顶部黄条「网络不可用，显示缓存」+ 重试按钮 |
| 搜索失败、无快照 | 红条 + 重试按钮 |
| 单包清单失败 | 该行类型标 `—`（放行不隐藏），不写缓存，下次自然重试 |

不自动重试、不做退避循环；`PI_OFFLINE=1` 时不发任何请求。

### 验收指标（手测/计数口径，非 UI 断言）

- 冷启：首批 8 行 <2.5s，50 行 <7s；
- 热回访（快照命中）：上屏 <50ms；
- 切 tab 往返 / 切筛选 / 开合菜单：**0 个网络请求**；
- 内存增量：<1MB（200 条列表 + kinds 表 + 快照解析产物）；
- 磁盘：单个 cache 文件 <100KB。

## 6. 动作接线（全部复用，不新造）

| 动作 | 复用 | 说明 |
|---|---|---|
| 安装 | `settings/plugins.rs::mc_install_package` | 传入 `npm:<name>`（**不钉版本**：钉版本会被 082 判 unsupported）；`normalize_source` 已能吃整条 `pi install …` |
| 卸载 | `mc_remove_package` + `cfg.pkg_confirm_remove` | 同 040 |
| 单包升级 | `mc_update_package(source)` | `pi update --extension <src>`（082） |
| 全部升级 | `mc_update_all_packages` | `pi update --extensions` |
| 收尾刷新 | `cfg.op_tx` op 泵（`shell/chat.rs`） | 泵里已做：清 `pkg_op` → 重读 `globals` → `reload_settings_panel` → `spawn_plugin_updates_check` → notify |

**关键点：市场页的「已装 / 有新版本」全部在渲染时实时派生，不另存副本**：

- 已装集合 = `cfg.mc_pkgs_global` 里的 source 归一化后与 `npm:<name>` 比对
  （`skills::entry_source` + `skills::display_source`）；
- 已装版本 = 新增 `skills::package_installed_version`（读
  `package_install_dir(source)/package.json`）；
- 有新版本 = `aux.plugin_updates.state_of(source) == UpdateAvailable`。

这样 op 泵刷新后市场页自动正确，不需要新增回调。打开市场页时若
`aux.plugin_updates.results` 为空，顺手触发一次 `spawn_plugin_updates_check`
（不阻塞首屏）。

市场页 v1 只认 **npm 来源**：git/本地路径装的扩展不出现在市场目录里，
「已安装」筛选只覆盖「市场目录 ∩ 已装」的并集（040 页保留，能看全量）。

## 9. 网络 / 代理 / 离线

- 搜索端点镜像不通：实测 `registry.npmmirror.com/-/v1/search` 返回
  `{"objects":[],"total":0}`（不支持搜索），**主路径必须 registry.npmjs.org**。
- 代理与镜像**不加设置项**（铁律：不动 Settings），只认环境变量：
  - `PI_FLASH_NPM_REGISTRY`（默认 `https://registry.npmjs.org`，拼 search/latest 的 base）
  - `PI_FLASH_HTTP_PROXY`（ureq `AgentBuilder::proxy`，`http://` / `socks5h://`）
  - 与 `PI_OFFLINE=1` 联动：置位则不发任何请求，只用缓存并把 `offline` 置真。
- `ureq` Agent：`timeout = 15s`、`set("user-agent", "pi-flash/<ver>")`、
  `Accept: application/json`；响应体截断 2MB（沿用 `probe.rs` 口径）。
- 失败分级：搜索失败 → `error` + 红条（缓存可用则退 `offline` 态）；
  单包清单失败 → 只影响该行 kinds，不报错。

## 11. 风险与分期

**已知差异（写进页面脚注或 PR 说明）**

- 官网 5407 条 vs npm `keywords:pi-package` 12364 条：站点做了额外收录规则，
  PF 以 `pi` 清单 + `pi.extensions` 过滤后条数会与站点不同，排序也可能逐条不一致。
- 「最新发布」排序无法服务端复现（npm 搜索只有 popularity/quality/maintenance
  权重）——v1 不提供该排序控件（需求也只要求默认最多下载）。

**风险**

| 风险 | 处置 |
|---|---|
| registry 不可达 / 被墙 | 环境变量代理 + 首页快照降级 + 明确黄条，不死转圈 |
| 一键安装跳过看源码这一步 | 页面固定安全提示 + repo 链接常显 |
| npm 搜索分页深度限制（未知具体上限） | 翻页 4 页（200 条）封顶，到顶提示缩小关键词 |
| 5247 条全量不可翻（有意为之） | 只做前 4 页；找冷门包靠搜索框（与网页体验一致） |
| 满页要 50 次清单请求（实测 ~5.5s） | 8 条一批流式上屏（首批 ~1.8-2.4s）+ 会话内 kinds 表命中 |

**分期**

- **v1（本次）**：入口三横菜单 → 市场标准页；搜索 / 未安装·已安装筛选 / 最多下载排序 /
  虚拟列表 / 安装 / 卸载 / 单包更新 / 全部更新(n) / 首页快照缓存 / 离线降级 / 安全提示。
  **内存预算 ≤1MB**：200 条列表 + 会话内 kinds 表 + 单文件快照，不做字典落盘/预取/深度翻页。
- **v2（另开 issue，先不做）**：行点开详情抽屉（README 摘要、`pi.image` 预览图 —— 需自建
  网络图片缓存，PF 现无网络图加载）、类型细分筛选、国内镜像索引、把 `pi list` 的
  git/本地来源并入「已安装」页签。
